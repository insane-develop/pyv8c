# 选靶与检查清单

目标是"用真站逼出 pyv8c 与真浏览器的差异"。站点随便挑，但要挑得值、挑得稳。

## 什么样的站点适合当靶子

1. **会主动探测浏览器细节**：bot wall、验证码门、指纹检测页、风控站。它们把差异直接放大成
   "页面走岔/被拦下"这种可观测结果，而不是藏在某次 API 调用的返回值里。
2. **重度前端**：外部 CSS、框架渲染、骨架屏、动画、懒加载。布局与级联的差异在这里最容易被逼出来。
3. **有明确的成功信号**：跳到目标页、出现某段文字、拿到某个值。判据要在动手前定好。
4. **稳定可复现**：同一 URL 连续跑两次结果一致。若站点本身按次数分流，就固定条件再比。
5. **允许访问**：优先公开页面、文档站、官方 demo、自家站点或你自己的测试站。
   不要打生产站的写接口，也不要为了通过而绕过站点本意（那属于站点条款问题，不是引擎问题）。

## 按引擎领域挑靶子

| 领域 | 拿什么压它 | 用哪些探针 |
| --- | --- | --- |
| 布局/块流/UA 默认值 | 任何有正文的页面（文档站、博客、新闻页） | `layout`、`ua` |
| 替换元素、画布、媒体 | 图片/图表/视频多的页面，论坛头像 | `replaced`、`layout` |
| 级联与样式表 | 外部 CSS 多、`@media`/`@supports` 多的站点（组件库文档最狠） | `style` |
| DOM 接口形状 | 任意 JS 应用的 landing 页 | `dom_api`、`rect`、`nodes` |
| 时间与动画 | 有轮播、骨架屏、loading 动画的页面 | `frames`、`timing` |
| 指纹面 | bot wall、验证码页、指纹 demo 站 | `globals`、`dom_api` |
| 事件与交互 | 要点一下/输入才出内容的页面 | `events` |
| 资源与网络 | CDN、自定义字体、懒加载的页面 | `style`、`layout` |
| 子框架/跨源 | 嵌第三方 widget / 验证码 iframe 的页面 | `layout` + 浏览器自己的 frame 列表 |

## 每个靶子的固定动作

1. **先只看 pyv8c**：`python scripts/harness.py --url <url> --probe all --side here --seconds 20`。
   记下它到底跑到哪一步——拿不到值也要记，那本身就是线索。
2. **两边跑**：去掉 `--side`，看逐字段差异。
3. **有差异** → 压成最小复现（写进 `probes.py`，带 fixture）→ 定性 → 处置。
4. **没差异** → 换更狠的探针（更多成员、更多节点、更长的等待、`--wait-for` 条件），或换靶子。
   探针越狠，"没差异"越有信息量。

## 反探测的常见形态（先怀疑页面，再怀疑引擎）

- 节点被换成包装：读属性得 `undefined`、`getOwnPropertyNames` 一堆自有属性——**两个引擎都一样**；
- 内容在跨源子框架里，父文档的 `textContent` 看不到；
- 同一 API 分两次给不同答案（先空后到），探针要覆盖"最终态"，不要只取第一次；
- 按 UA / WebGL / 字体 / 时区 / 语言分流：两侧环境档案不一致就会走到不同分支——先比环境档案；
- 主动隐藏、延时渲染、需要交互：用 `--wait-for <js>` 等条件，不要等固定时间。

## 差异定性的三分法

| 现象 | 判据 | 处置 |
| --- | --- | --- |
| pyv8c 缺实现 | 日志里出现 `待实现`，或该方法返回 `undefined`，或接口整个不存在 | 实现它（按 `../SKILL.md` 的表定位） |
| pyv8c 语义不同 | 两侧都能跑，数字/顺序/类型不同 | 改引擎，用同一探针验证，跑回归 |
| 页面行为 | **同一个读数在 Chrome 里也一样**（包装、隐藏、延时、分流） | 判定为"已排除" ✓，写进**探针的注释**里（说明它为什么不是引擎问题 ✓），再决定改自己的代码或绕开 |
